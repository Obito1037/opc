# 映身 v0.4 · 项目说明

更新：2026-10-21（北京时间）。定位为数媒比赛交互原型，尚不是完整商用试衣平台。

v0.4 已连接人物与商品上传、同源任务 API、CPU 换衣、自有默认轻微姿态与自带视频动作实验。最新正式 **5173** 界面端到端验收通过，无 mock、浏览器异常 0；换衣任务耗时 **258.206 秒**、自有 `owned-subtle` 动作任务 **67.902 秒**。刷新后恢复任务、PNG/视频下载与 API 字节一致、视频实际解码 24 帧并播放到结尾、Range 请求均通过；随后生成图成功进入“继续搭配鞋饰”，真实本地识别完成并打开商品窗口，见 [最新完整报告](../test-results/generation-v4/release-production/real-generation-report.json)。人物为 AI 示例、商品为研究图、默认驱动为自有人台动画，这个流程通过不等于所有用户画质已通过。此前 5176 的研究视频驱动检查保留为 [历史报告](../test-results/generation-v4/real-production/real-generation-report.json)，v0.3 的检查保留为 [历史记录](验收记录-v0.3.zh-CN.md)。

本轮新增自己的商品图片试搭、色卡取色，以及 AI 种子选择 / 新变体。完整 `npm test` 实际 **61 / 61 通过，0 跳过**；商品引擎 30 项浏览器像素检查使用合成关键点，商品窗口另有 **11 组真实本地识别检查通过、0 页面异常**，见 [窗口报告](../test-results/product-v4/ui-real/product-ui-real.json)。实际 MediaPipe 检测未被替换；人物使用 AI 示例、眼镜 / 鞋 / 色卡为程序绘制图形，不能把这些检查计入真实商品贴合或神经生成画质验证。

## 问题与作品目标

网购时，用户难以把商品图片与自身形象联系起来；衣服、鞋履、配饰和妆容的选择分散，静态图片也难表达动作中的视觉效果。映身尝试把照片预览、搭配陈列和真实视频试妆放在一个工作台中。

这些痛点和“降低退货率”的潜在价值仍需用户研究验证；当前没有真实交易、退货率或商业增长证据。OPC 暂按个人或小团队可维护的产品组织工程，具体赛事定义和申报规则仍需按实际赛道核对。

## 从 v0.2 到 v0.4

首版照片采用几何衣服覆盖、人物抠图和局部网格动作，实际效果存在纹理被遮盖、轮廓破碎、肢体变形。v0.2 改为保留完整原图，对可靠识别的现有上装改色；保留原来的面料纹理、褶皱与光照。遇到复杂印花等不可靠输入时保留原衣，不显示虚假的换装成功结果。

独立的“动态试妆”让妆容、眼镜和耳饰跟随摄像头或本地视频中的真实动作。照片模式只做轻微运镜，不再模拟人的行走或挥手。三维陈列继续提供服装组合和程序动作，并升级 MakeHuman CC0 连续蒙皮人台、17 骨骼；它始终是独立人台，不是照片重建的用户本人，整体验证另见验收记录。

v0.3 继续改善实际使用过程：把绿色侧栏和装饰大字替换为顶部导航、银灰工作区和蓝色控件；提供深浅主题与专注预览，让内容成为视觉重点。左侧编辑、中央预览、右侧衣橱在桌面形成稳定分区，手机改为单栏。设计参考与取舍记录在 [设计来源](design-references-v3.md)，不是 Apple 官方组件或 Liquid Glass 实现。

新增最多 40 步撤销 / 重做，连续滑条操作合并、自定义颜色、原图与效果分屏；收藏可重命名并以 JSON 导入导出，仅交换名称和搭配参数。工作台设置提供自动适配、流畅优先和精细画质，三种陈列背景，以及减少动态选项。快捷键支持撤销、重做、收藏、暂停和专注模式，同时保留输入框的原生编辑行为。

v0.4 把人物和真实商品图片联系起来：点击“AI 试穿与动作”，选择平铺或白底商品图，提交本机 CatVTON。服装解析由 FASHN 18 类模型区分目标区域，上衣用 `vitonhd-16k-512` attention 权重；384 × 512、CPU FP32、24 步的实际样片约用时 267 秒，合回 1024 × 1280 人物图。见 [真实结果](../test-results/vton-v4/quality-semantic-24/result.png) 和 [报告](../test-results/vton-v4/quality-semantic-24/report.json)。该图使用标注的 AI 人物示例，不能充当真实用户泛化测试；商品轮廓与细节仍可能变化，下装和连体服装还需单独验收。

AI 任务新增可选整数种子 `0–2147483647`。留空时服务端为每个新任务随机选择一次，实际值传给 Python `--seed` 并随任务保存；刷新、历史和服务重启不重新抽取。可复用种子，或再次生成新变体。相同种子的复现还依赖相同输入、模型与其余参数，旧记录缺少种子时不补造。测试覆盖边界、进程参数与恢复；最新正式换衣任务实际种子为 `42`，尚未进行多随机种子变体的画质对比。

照片模式新增“上传自己的鞋饰 / 色卡”：上传自己的透明 PNG 或普通商品图，本地可选去除边缘连通白底，按检测到的双眼、双耳、双肩或双脚定位眼镜、耳饰、项链和鞋履。支持缩放、旋转、偏移、透明度与镜像，检测不足时说明原因。色卡可点击 / 键盘取色，用于唇颊预览。它不重建商品视角、不消除原鞋饰，也不生成真实遮挡；界面明确标注二维试搭和实物色准限制。实现与证据见 [商品试搭记录](product-overlay-v4.md)。

成功换衣结果新增“继续搭配鞋饰”，把生成图载入照片工作台并运行本地识别，然后进入商品图 / 色卡窗口。正式 5173 的最终整链路已实际通过：无需重新上传，载入后停用原衣调色，保留已生成的服装，再在同一人物画面中继续搭配。

独立动作流程接收人物图或成功试穿结果，再上传用户自己的短视频。用户也可点“用首帧作为人物照片”，在浏览器本地提取视频首帧并替换当前人物图，以对齐起始姿态；只准备输入，不自动上传生成。PyAV 完整校验并保比例整理素材，TPS 再逐帧生成小幅体态变化，输出 3 秒 / 8fps / 256 × 256 的实验 MP4。真实 24 帧样片及 UI 链路已经运行并重放；本轮仍使用不同人的研究驱动，不能当作用户本人输入效果已通过。完整证据与限制见 [用户驱动动作记录](motion-user-driver-v4.md)。

单图默认动作仅批准 `owned-subtle`“轻微姿态 · 实验”，驱动来自项目自有 CC0 人台与原创骨骼动画，照片输出仍经过真实 TPS。固定 3 秒 / 8fps / 256p、幅度 0.5、驱动规范化；此前单例 AI 模特推理 69.457 秒，24 帧均不同，人工质检限定接受，`generalQualityPassed:false`。本轮正式界面实际耗时 67.902 秒，完成播放与下载检查。头肩小幅变化可见，脸部柔化 / 形变仍存在，腿部近静止，不能宣称高质量全身动作或身份 / 衣物纹理保证；所有研究驱动预设继续禁用。见 [自有驱动和质检](motion-owned-driver-v4.md)。

## 技术与复用

MediaPipe Pose Landmarker、Face Landmarker 和衣物语义分割用于本地分析；服装置信度、上衣颜色筛选和边缘引导滤波共同构建改色区域，按原图亮度保留褶皱。动态试妆使用 FaceLandmarker VIDEO 模式逐帧检测，而不是把静态照片预制成视频。

Three.js 负责三维陈列；MakeHuman CC0 基础网格用于替换首版简单程序人台。检测器、渲染引擎和基础模型均应列出上游来源，作品贡献主要是交互流程、局部质量控制、多种预览方式的统一呈现和低配置本地运行，不能把上游模型能力宣称为原创算法。

v0.3 的工程改进围绕减少无效计算：按需加载引擎；3D 在暂停且相机稳定后停止连续绘制，交互再触发更新；照片更新合帧与合成缓存；视频人脸推理使用本地 Worker 支持路径，避免把每次识别都直接挤到界面线程。它们改善的是调度和响应方式，并不提升识别模型本身的服装理解能力。

3D 短时对比观察到暂停稳定期间重复绘制从有变为无，但活动采样没有显示帧率提升；两版默认阴影成本也不同，不能称为等画质 GPU 基准。照片测试确认同一帧内 60 次妆容修改合并为 1 次完整合成；视频专项确认真实本地模型在 Worker 中运行，并保留 Worker 不可用的限频回退。照片首次识别仍在主线程分阶段执行。硬件、采样时长、输入与实际结果详见 [3D 性能专项](performance-avatar-v3.md)、[照片与视频专项](performance-vision-v3.md) 和 [v0.3 验收汇总](验收记录-v0.3.zh-CN.md)。

GitHub 复用包括 Three.js / MediaPipe / MakeHuman，以及 CatVTON、FASHN 服装解析与 Thin-Plate Spline Motion Model。界面参考 Radix Themes 的主题组织与 Vaul 的次级操作呈现，二者已核验 MIT；没有安装它们的 React 依赖。Vaul 核验时已声明不再维护，因此只作为设计参考。

本机隔离环境和实际权重已安装，无需 CUDA 或商业密钥即可执行当前 CPU 换衣。FASHN 远程适配器继续可选，尚未配置商业 key、未做付费生成；早期公共 Space 额度失败是 [历史服务记录](ai-provider-research-v2.md)，不代表后来本机方案的状态。CatVTON 与服装解析权重保留非商业研究许可限制，不能把代码可运行等同于已具备商业授权。

Node API 与页面同源，只监听本机。所有生成共享一个槽，真实上报步数/帧数及经过时间；缺少模型、坏输入、取消或失败均返回实际状态。上传图片各限 12 MiB，用户驱动视频同样限 12 MiB，需 3–15 秒、8–60fps、最高 1080p。任务结束清理输入，结果最多保留 24 小时，支持下载和删除。浏览器只保存任务编号；配置、密钥和本机路径不外显。细节见 [换衣接口](tryon-api-v4.md) 与 [动作接口](motion-api-v4.md)。

本地商品窗口与上述 AI 上传流程独立：图片通过 Object URL 解码后存于内存 Canvas，未调用网络上传、localStorage、sessionStorage 或 IndexedDB。关闭窗口会保留当前页试搭，移除商品 / 更换或清除人物照片 / 刷新后释放。色卡取色只把颜色值写入搭配参数；用户主动导出才创建本地下载文件。该结论来自入口与模块的静态代码审查，窗口实测网络记录应另列证据。

从源码运行先 `npm test`、`npm run build`，再 `node scripts/serve.mjs`；Vite 开发服务本身不提供这些 AI 接口。管理员配置 `runtime/config.json` 选择本机模型，环境变量可覆盖；示例文件不会自动生效。`configured:true` 允许首个真实任务，`available / verifiedGeneration` 要等当前服务进程的有效输出，服务重启后重新验证。最新真实界面运行脚本与证据为 `tests/generation-real-v4.cjs` 和 `test-results/generation-v4/release-production/`，不包含 mock 成功结果。

默认白 T 全身样片是 AI 生成示例，不能当作真人实测数据。原 CC0 走秀照片保留用于复杂场景回归。照片调色需要更多真实肤色、光照、服装和遮挡输入验证，不能从单个清晰样片推导普适质量。

## 比赛竞争力与下一步

v0.4 已在此前界面和性能工作上增加商品上传与真实 CPU 服装替换，并连接实验性视频驱动。单个上衣样片与短动作还不足以证明已解决所有网购试衣困难：商品纹理精确度、多种体型与复杂遮挡仍需验证，没有尺码评估、商家库存或交易系统，也没有退货率改善数据。

1. 保留已通过的真实提交、刷新恢复、结果下载和视频播放证据，继续扩展长时间使用、真实用户取消/删除与异常恢复检查；不将协议测试替代模型画质评估。
2. 扩充上衣、下装和连体商品样本，记录人物保持、图案、遮挡、失败率和实际耗时；不可靠输入如实失败。
3. 验证用户本人驱动视频及更丰富真人样本，分别评估 AI 动作、实时配饰跟踪和独立三维陈列，避免混淆能力。
4. 按真实赛事标准打磨交互、原创贡献说明、素材授权、作品视频和离线备用方案。
5. 有用户任务测试与真实成本数据后，再讨论商业方式；不编造转化率、退货率或运营收入。
