## v0.4 真实生成

点击顶部 **AI 试穿与动作**，上传人物图和平铺 / 白底商品图，按当前服务支持的类型提交。工作台可查看真实阶段、步数与经过时间，取消任务、恢复本机记录、比较原图、下载或删除结果。浏览器仅保存任务编号，不把上传图片塞进 localStorage。没有配置时显示真实原因，不用改色结果冒充 AI 成功。

成功结果新增 **继续搭配鞋饰**：将生成图载入照片工作台、本地分析后打开商品窗口，再添加自己的鞋饰或色卡，无需重新上传。当前最终版本的“换衣 → 默认轻微姿态 → 继续鞋饰”整链路已通过上述正式服务检查，载入时停用原衣调色以保留 AI 结果。

生成设置可留空种子，每个新任务由服务端选一次随机值；也可输入 `0–2147483647` 整数。任务保留实际种子，支持复用种子或再次生成新变体，重启后仍能读取；旧记录没有种子时不补造。复现需要保持输入、模型和其他参数一致，不能把相同种子等同于画质保证。接口、Python 参数与恢复已用隔离 fixture 验证，最新正式任务实际记录种子 `42`；尚未开展多随机种子的画质对比。

当前 CatVTON 以 CPU FP32 运行，采用 FASHN 18 类服装解析构建蒙版。上衣已用 `vitonhd-16k-512` 权重完成 24 步样片，约 267 秒，输出 1024 × 1280；这是此机器、此输入的一次记录。服装细节与商品仍有差异，不能视为精确图案、尺码或面料还原。下装和连体类别仍待单独画质验收。

动作工作台可使用成功试穿图或人物图，再上传自己的短动作视频。也可点击 **用首帧作为人物照片**，在浏览器本地提取视频首帧、替换当前人物照片，让起始姿态更一致；该操作不会自动提交生成。视频在本机完整校验、去音轨并保比例整理后进入 TPS 神经模型，固定小幅度生成 24 帧。原始视频要求 3–15 秒、8–60fps、最高 1080p、最多 12 MiB；建议固定镜头录制 4–6 秒。该入口需服务端显式启用，效果仍属实验，不承诺走秀或任意转身。后端契约见 [换衣 API](docs/tryon-api-v4.md) 和 [动作 API](docs/motion-api-v4.md)。

单图默认动作目前只批准 **轻微姿态 · 实验**：复用项目自有 CC0 人台和原创骨骼动作作驱动，人物结果实际经过 TPS，固定 3 秒 / 8fps / 256p、幅度 0.5。单例 AI 模特的早期真实推理约 69.457 秒，已人工限定接受；本轮正式界面任务 67.902 秒并完整播放通过。脸部柔化、局部形变和腿部近静止仍存在，不保证身份或纹理保持；所有未通过的研究视频预设继续禁用。见 [自有动作来源与质检](docs/motion-owned-driver-v4.md)。

## 自己的商品试搭

上传人物照片后点击 **上传自己的鞋饰 / 色卡**，选择自己的眼镜正面图、单只耳饰、项链或鞋头朝右的单只侧面鞋图。支持透明 PNG，以及本地可选去除与边缘相连的白底；可调大小、位置、旋转、透明度和镜像。眼镜使用双眼，耳饰使用检测到的双耳，项链使用双肩，鞋履使用双脚的踝 / 跟 / 趾关键点。检测不足时保留照片并说明原因，不猜位置。

**妆容 · 从色卡取色** 可从自己的色卡图片选择唇颊预览颜色，也可直接选色号。商品图片和色卡留在当前页面内存，刷新或清除后释放；照片原图对比不含叠加，商品窗口导出包含当前试搭与参考说明。该入口是二维搭配预览，不移除原鞋饰、不模拟遮挡或真实贴合，也不保证实物色准。实现、来源与分层证据见 [商品试搭技术记录](docs/product-overlay-v4.md)。

## v0.3 新增体验

- **更清楚的工作台**：顶部导航、亮暗主题、手机单栏布局和专注预览。借鉴 Apple 设计原则与 GitHub 上 Radix Themes、Vaul 的组织方式，采用原创 CSS，不新增 React UI 库。具体采纳与许可核验见 [设计参考](docs/design-references-v3.md)。
- **可撤回的搭配编辑**：最多保留 40 步历史，支持撤销、重做与恢复默认；连续调色和妆容滑条操作合并，避免每次微调占一步。历史只包含搭配参数，不包含照片或视频。
- **更方便比较**：原图 / 效果分屏滑条，支持照片和已经开启的动态试妆；可选任意服装颜色，仍保留原图查看入口。
- **适合设备的显示**：浅色 / 深色 / 跟随系统；自动适配 / 流畅优先 / 精细画质；珍珠白 / 深空灰 / 柔雾粉背景；减少动态选项。设置保存在当前浏览器。
- **可带走的灵感**：收藏重命名、JSON 导入导出；最多 24 套，单个导入文件最大 64 KB，只保存经过校验的名称与搭配参数。
- **减少无用工作**：初始页面按需加载引擎与识别资源，3D 暂停稳定时停止连续绘制；照片更新合帧并缓存合成，视频人脸推理使用 Worker 支持路径。性能证据与适用范围见 [v0.3 验收记录](docs/验收记录-v0.3.zh-CN.md)，不将短时间采样称为所有设备的帧率提升。

专项数据分别见 [3D 调度与画质](docs/performance-avatar-v3.md)、[照片与视频推理](docs/performance-vision-v3.md)。照片首次识别仍在主线程分阶段执行，不能把连续调整的优化理解为首次加载完全无阻塞。

在工作区根目录双击 [Open-TryOnStudio.cmd](../Open-TryOnStudio.cmd)，访问 [映身工作台](http://127.0.0.1:5173)。已有 dist 时，启动器启动本地页面与同源 API 服务；源码修改后需要重新构建。AI 服务配置在启动时读取，是否就绪以工作台状态为准。

当前使用 Node.js 24.18.0；从源码构建需要 npm 和满足 Vite 要求的 Node.js。启动器兼容 PATH 和本机 D:\node\node.exe，只监听 127.0.0.1。检测到同一个映身服务会复用，端口被其他程序占用时会提示，不会结束其他程序。

## 预览与 AI 生成

| 入口 | 已实现的方式 | 使用边界 |
| --- | --- | --- |
| AI 服装试穿 | 人物图 + 商品图，本机生成替换结果；真实 UI/API 链路已验证 | 上衣细节不保证一致，下装/连体仍待画质验收 |
| 自己的商品图 / 色卡 | 鞋履、眼镜、耳饰、项链按本地关键点二维叠加；色卡取色用于妆容 | 不改变商品视角或生成遮挡，不测尺寸；不是全品类神经换装 |
| 自带动作视频 | 人物图或试穿结果 + 本人短视频，TPS 神经动作迁移 | 3 秒 / 8fps / 256p，小幅正面实验；不是任意走秀或背面服装重建 |
| 单图轻微姿态 | 自有 3D 驱动 + TPS 神经生成，限定实验预设及正式 UI 流程已验证 | 单例 AI 模特样本；可能影响身份、脸部与衣物纹理 |
| 照片改色 | 上传照片，本地识别人体、人脸与衣物；对现有上衣调色，保留真实纹理、褶皱、原背景和身体轮廓 | 不改变版型，不移除原衣物；复杂印花或不可靠区域保持原样 |
| 动态试妆 | 摄像头或本地视频中跟踪人脸，叠加唇颊妆容、眼镜和耳饰 | 动作来自输入视频中的真实人物；不是单张照片生成视频，不提供视频换衣 |
| 3D 陈列 | 独立的服装陈列人台，支持动作、旋转与缩放 | 使用 MakeHuman CC0 连续蒙皮网格、17 骨骼；不是上传者本人重建 |

照片改色模式默认不绘制几何上衣或鞋子。只有主动启用“轮廓草图”才显示示意覆盖。该模式的轻微动态只是运镜；生成式动作使用独立 AI 工作台，实时妆容跟踪使用“动态试妆”。

目录保留服装、鞋履、配饰和妆容四类参数化示例。衣服款式与鞋履主要在 3D 陈列中展示；照片改色只使用颜色，动态试妆只使用妆容及适用面部配饰。支持原图/原视频对比、暂停、搭配收藏、PNG 导出，以及浏览器支持时的 6 秒 WebM 录制。

浏览器照片预览支持 JPG、PNG、WebP，最大 16 MB；动态试妆支持可解码的 MP4、WebM、MOV，最大 200 MB。AI 生成的图片和驱动视频各限 12 MiB，驱动只支持 MP4/WebM，限制与前述浏览器预览不同。格式后缀不能保证内部编码可用。摄像头需要浏览器授权；设备不可用或授权被拒时，可上传本地视频。

## 本机模型与可选云端

本机隔离 Python 环境、CatVTON 及服装解析权重已经安装，并已通过真实 UI/API 生成验收。`configured` 表示可以提交任务，`verifiedGeneration` 表示当前服务进程已拿到有效生成结果，不能把二者混用；服务重启后的首次验证状态会重新开始。CLI 画质样片、真实界面流程及协议 fixture 均分别保留记录。

服务器读取 `runtime/config.json`，环境变量优先；[本机 CPU 配置说明](docs/tryon-api-v4.md) 与 `runtime/config.local-cpu.example.json` 提供示例。自带动作示例 `runtime/config.custom-motion.example.json` 保持未启用，只有显式启用且模型齐全才公开入口。示例文件不会自动生效。模型运行不需要 FASHN 密钥，配置路径与密钥不发送浏览器。

FASHN 云端换衣 / 图生视频适配器继续可选，商业 key 尚未配置，未执行付费生成。早期公共 Space 的 GPU 额度失败保留在 [历史服务记录](docs/ai-provider-research-v2.md)。CatVTON 与服装解析权重有非商业研究许可约束，保留来源声明，不将此版本直接表述为已具备商业授权的平台。

## 从源码运行

在 TryOnStudio 目录执行：

~~~powershell
npm ci
npm run setup:models
npm run dev
~~~

以上 Vite 开发命令用于浏览器预览；AI 同源接口需要下方的 Node 服务。`setup:models` 准备浏览器识别资源，不等于安装 CatVTON。已齐全资源不必重复下载，WASM 和浏览器模型摘要记录在 public/models/manifest.json。本机换衣依赖安装脚本为 `scripts/vton-v4/install.ps1`，真实模型清单位于 `runtime/vton-v4/models/manifest.json`；本工作区已准备好。

构建交付版本：

~~~powershell
npm test
npm run build
node scripts/serve.mjs
~~~

开发服务和交付服务默认共用 5173，不能同时占用该端口。修改源码后须重新构建并刷新。完整本机 AI 交付需保留 dist、server、scripts、对应 runtime Python 环境/模型、asset-sources 中实际依赖的官方代码与权重、根目录启动器及可运行 Node.js，不能只复制 dist。不要打包个人上传、生成历史或密钥。应用不能直接双击 dist/index.html 使用。

## 常见问题

- 衣服没有改色：可能是复杂印花、区域不可靠或未识别到完整躯干；程序会保留原图。优先使用光照均匀的单人正面上身/全身照片。
- 选择连衣裙后照片版型没变：照片默认只改原衣颜色；款式去 3D 陈列观察，轮廓草图也不等于真实换衣。
- 妆容没跟上：人脸太小、遮挡或快速转头可能丢失跟踪；回到清晰正面后重新识别。
- 摄像头不可用：检查浏览器与系统设备设置，或改用本地视频。
- 3D 黑屏：使用支持 WebGL 的 Edge/Chrome，并检查硬件加速。
- 交互卡顿：在右上角设置中选择“流畅优先”，或暂停动作；“精细画质”增加绘制成本，不适合所有设备。
- 只看见部分衣橱：桌面左右面板支持独立滚动；也可调整浏览器窗口。专注预览暂时隐藏两侧面板，可点击顶部按钮或按 F / Esc 返回。
- 收藏文件导入失败：只接受映身导出的 JSON 格式；文件须小于等于 64 KB，导入后总收藏不能超过 24 套。JSON 不携带人物照片。
- 无法导出 WebM：浏览器需支持 captureStream 和 MediaRecorder，可先导出 PNG。
- 页面未更新：重新运行 npm run build 后刷新。启动器日志在工作区 setup/verification/tryon-server.*.log。
